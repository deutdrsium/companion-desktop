# Desktop session wire v1

`companion.desktop.v1` uses UTF-8 JSON. `types.py` defines shared types and `wire.py` validates the envelope, directions and message bodies. Synthetic branches for resource support, execution evidence, cancellation and current windows are in `tests/fixtures/contract/replay.json`. The installation supplies the authenticated HTTPS endpoint and the paired device credential.

## Transport

A single POST endpoint accepts `{operation, payload}` and returns `{status: "ok", data}` or `{status: "error", reason}`. The encoded UTF-8 request body can be up to 262,144 bytes, including the operation and all payload fields. Registration accepts `{protocols, permissions}` and returns `{protocol, session, permissions}`. The authenticated host derives the binding and assigns `session = {device_id, desktop_session_id, generation}`. Treat the entire reference as the identity of the connection. A generation increases within a running host. The host assigns a new session ID after restart as well.

Current desktop clients include `activate_on_exchange: true` in `register`. The host reserves the reference for one lease period and makes it current on its first valid `exchange`. Activating a generation discards older reservations for the same device. A `disconnect` can also discard an unused reservation. A delayed registration response can only leave an unused reservation when its client has already exited. Upgrade the host integration before using a desktop client that sends this field. Clients that omit it retain immediate registration.

`exchange` and `disconnect` accept `{session, messages, turns}`. `messages` contains up to 32 client envelopes `{protocol, type, session, body}`. `turns` contains up to 32 pending `client_msg_id` values to reconcile. `exchange` returns `{messages, permissions}`. `disconnect` retires that generation and returns `{}`. The host rechecks credentials and the bound role/window for every request. The device must refresh the connection before the 20-second idle lease expires. Legacy clients can keep their independent HTTP/SSE flow.

`permissions` independently grants `avatar`, `game`, `observe` or `speak`. Send `capabilities` after registration and again after a model or resource change. Increase `revision` when the declaration changes. `games` contains the capabilities of currently registered games. A game adapter registers the active decision window on both sides. Replacing the window or revoking access invalidates prior tasks. The current `role_state` and matching `wardrobe` snapshots follow capability publication, with newer revisions sent as they change. The host recomputes remaining TTL before dispatch. The client subtracts exchange elapsed time and uses a monotonic deadline. A single-shot intent or utterance goes out in its original generation only. Capability replacement releases old local output and invalidates old callbacks.

## Local session API

`companion_desktop.session.client.Session` specifies the UI interface. `DesktopSession(transport, permissions=..., avatar=..., game=...)` and `InMemorySession()` implement it. The real session runs on its owning asyncio loop. `start()` schedules it, `await close()` releases outputs and disconnects, and `subscribe(listener)` returns an unsubscribe callback. `connection` and `capabilities` expose the latest view. The subscription emits flat dictionaries whose `type` names the event. `next_retry_ms` is a relative delay for the current `attempt`. Effective UI capability fields are `tts`, `mouth`, `subtitle` and `observe_scopes`.

`send_message(client_msg_id, text)` reports `turn.accepted` or `turn.failed`. Both events carry `client_msg_id`, and a pre-delivery local failure carries a null `turn_id`. Use the same ID and text to retry. A different payload with the same ID is rejected. Accepted turns can produce `turn.completed` with complete clean text and optionally `turn.text` with `turn_id`, a 1-based `seq` and clean text. The P1 WebChat adapter publishes complete text. `cancel_turn(turn_id)` requests cancellation and reports `turn.cancelled` with `unknown` until authoritative evidence supports `cancelled`. A reply that already completed can still arrive. The host retains durable claims for the bound window and uses the existing conversation for history recovery.

P2/P4/P6 supply `Output.start(intent, deadline=..., is_current=..., report=...)`, `cancel(intent, reason)` and `release(reason)` from `session.dispatcher`. An avatar output additionally supplies `snapshot(kind, body, deadline=...)`. Check `is_current()` immediately before effects. Report with `OutputResult`, including `{source, ref}` evidence for completion or confirmed cancellation of started effects. Call `publish_capabilities(body)` with the new model/game declaration and `set_permissions(scopes)` on local revocation. P6 calls `set_game_window(game_session_id, window_id, window_revision, deadline=...)` with an absolute local monotonic deadline, or `window_id=None` on takeover. P4/P5 can send `wardrobe_applied` or `observation` with `report(kind, body, session=...)` using the originating session reference.

Mapped `activity.*`, `outfit.*`, `accessory.*` and `expression.*` intents select one
entry in their own group. `event.*` reports `completed` when VTS acknowledges the
hotkey trigger. The `vts_hotkey_ack` evidence confirms dispatch. These intents
take empty `params`. A wardrobe snapshot can select
`outfit` by name and set complete `accessories` or `expressions` lists. Omit a group
to leave it unchanged or send an empty list to clear it. A mapped `role_state.activity`
selects the corresponding pose while that snapshot is current. Persistent state
receipts require expression state and Live2D parameter readback.

U1 can consume `observe.state` with `request_id`, `source`, `phase`, `result`, `captured_at` and `license_generation`. The session emits `requested` for a live, supported `observe` frame and `done` when the originating adapter reports `observation`. P5 emits `capturing` with `observe_state(body, session=...)` after its local consent recheck. The embedding host can queue `send_observe(ref, body)` and receive observation results through `on_message` after rechecking its permission generation.

P3 subscribes to `utterance`, `cancel` with an `utterance_id`, and connection changes on the desktop. The embedding host calls `SessionHost.send_utterance(ref, body)` and `cancel_intent(ref, utterance_id=...)`. The WebChat bridge sends cue-bearing segments in the same exchange as `turn.completed`. For this bridge, `utterance_id` equals `turn_id`, `segment_id` is the zero-based sentence index encoded as a string, and `text_offset` counts Unicode code points in the clean segment. Recovered turns carry text only. The desktop synthesizes clean sentences through the existing `/speech` endpoint, and drives the mouth from the WAV and local player position.

```json
{"turn_id":"turn-demo","utterance_id":"turn-demo","segment_id":"0","text":"看🐟。","audio_id":null,"cues":[{"task_id":"turn-demo-cue-0","action":"nod","params":{"intensity":0.5},"text_offset":1}]}
```

The existing v1 envelope and validation are unchanged. A cue can carry `params.audio_offset_ms` as an integer measured from the start of the clip when its segment's `audio_id` matches that clip. P3 uses code-point interpolation over the measured player duration when the identifier or timestamp is absent. The current WAV provider supplies no timestamps.

The host embedding uses `SessionHost.current_session(device_id)`, `capabilities(ref)`, `send_intent(ref, body)`, `cancel_intent(ref, task_id=...)`, `receipt(ref, task_id)` and `wardrobe_applied(ref)`. Desktop and host must validate the scope and capability revision. Repeating the same task ID and business fields returns the existing receipt. A missing game window, expired TTL, removed permission or mismatched model prevents execution. An unknown result requires evidence tied to the original operation for reconciliation.
